## What is built
- **The shape of a reader's answer** (what the M2 function will have to return, and what
  the M1 fixtures are): `{ "rows": [ … ] }`, each row with `term` (the heading as printed),
  `transfer` (true for the transfer-credit section), `prefix`, `number`, `description`,
  `attempted`, `earned`, `grade`, `points`. It carries nothing about the student.
- `src/reader.ts`, plain code with no dependency:
  - `readRows(answer, curriculum)` checks the answer and returns, in the order read: the
    rows that passed the check, each as a transcript row (`TranscriptRow`, F03) with its
    printed description and how it matches the curriculum; the rows that failed, each
    with what was read and why it failed; and how many lines were thrown away as not
    being courses. An answer that is not a list of rows at all is refused outright.
    Fields the shape does not name are ignored and never copied into what is returned.
  - `standingsOf(reading, grades)`: the course standings (F03) of the rows that passed,
    and of those only. This is the one way from a reader's answer to `placeCourses`.
- **The check, per row** (each row is read field by field from its own named fields):
  - *shape*: the row is an object; `term` is text and not empty; `transfer` is exactly
    true or false; `description`, if present, is text; `grade` is text or nothing;
  - *course code*: `prefix` is text that, trimmed, is two to four letters; `number` is
    text that, trimmed, is three digits, or a whole number from 100 to 999; together they
    are the course code (so a lab such as BIOL 127 is its own course, and a prefix
    "ENG131" with an empty number is a fault);
  - *credits*: `attempted` is a number, or text that trimmed is a plain decimal number
    ("3", "3.00"), from 0 to 30 with at most two decimals. On a transfer row it may be
    empty (missing, null or ""), and the row's credits are then 0. `earned` and `points`,
    if present and not empty, are numbers or such text; they are otherwise not used;
  - *grade*: for a row outside the transfer section, the grade is judged by `rowStanding`
    (F03) and by nothing else: only a grade it calls unrecognised is a fault. Nothing,
    or "", is "in progress"; a letter of the curriculum's scale passes or must be
    repeated; a never-counting mark counts nothing: all of these pass the check. A
    transfer row's grade column is not judged.
- **Matching** is by course code only: a row is "listed" (in a curriculum list),
  "elective" (an elective by the rule only) or "none" (it can fill nothing). The
  description is never used to match or to count: it is kept to be shown, and read only
  to recognise the lines thrown away.
- **Lines that are not courses**: the Term GPA, Transfer Term GPA and Combined GPA totals,
  the "Academic Standing" line and the transfer section's "Transfer Totals" line. When a
  reader returns one as a row, it is thrown away: neither a row that passed nor a row to
  fix. A row is thrown away only when its prefix or description carries one of these five
  phrases (any letter case) **and** its prefix and number are not a course code.
- **Two made-up transcripts** in `synthetic/transcripts/`: for each, a PDF laid out like
  the real unofficial transcript and a file with the reader's answer for it; and
  `scripts/make-synthetic-transcripts.mjs`, which writes the PDFs from the answers (plain
  code, no dependency, the same bytes every time), so the two cannot drift apart.

## Decided here (recorded in `docs/decision-log.md`)
- **F10 is finished together with F11** (see "User-visible change").
- **The shape of a reader's answer** (above): flat rows, each carrying its term and whether
  it is in the transfer section, and nothing about the student. The M2 function (F21)
  must return this shape; it may change only by a recorded decision that updates this
  feature's checks in the same pull request.
- **Numbers may arrive as text** ("3.00", as a transcript prints them); **0 to 30 with at
  most two decimals** is a sanity range, not an academic rule. Credits never come from a
  transcript row anyway (F03, F04): the row's number is only shown.
- **"Transfer Totals"** is the made-up PDF's wording for the transfer section's totals;
  the real wording is to be confirmed on the owner's transcript in F21.
- **Where the made-up transcripts live**: `synthetic/transcripts/`, outside `src/` (which
  may hold no course code) and outside `tests/` (F11's localhost upload uses them too).
- **The made-up student** is "Sample Student", ID 000000000, and every page of each PDF
  says "SYNTHETIC — not a real transcript". No summer term is in the made-up transcripts:
  the owner has given the headings "Fall 2023" and "Spr 2024" only (how a summer term is
  printed is asked when F15 needs it).

## Acceptance checks
Tests are in `tests/reader.test.ts`; made-up data only.

1. **A clean answer.** The answer for `sample-a` gives only rows that passed, in the order
   read, none to fix; each has its code in normal form, its term, credits, grade and
   transfer flag, and its printed description. — "reads a clean answer row by row".
2. **Nothing counts before the check.** `standingsOf` takes only a checked reading; the
   standings it gives are those of the rows that passed, and placing them gives, for
   `sample-a`, 27 credits done, 13 in progress and 81 left, with ECO 251 in progress (its
   earlier D does not count) and the sequence still needed. — "places the made-up student
   of the design".
3. **An invalid row is never counted and is kept for fixing.** For each of these, alone
   and mixed into `sample-a`: the row is among the rows to fix with its reason and what
   was read, it is not among the rows that passed, and the placement is exactly that of
   the answer without it: not an object (text, a number, null, a list); no `term`, or an
   empty one; `transfer` missing, "yes", "no", 1 or null; a prefix or number that makes
   no course code ("ENGL1", "13", "131A", "", 13.5, prefix "ENG131" with an empty number,
   prefix "E"); `attempted` as text that is not a plain number ("", "3 cr", "1e1", "0x3",
   "Infinity"), negative, 31, 3.005, NaN or missing on an ordinary row; a grade that is a
   number; a grade not on the scale ("B+", "P", "X") on an ordinary row; `description` as
   a number. A row with several faults lists each. — "sets aside a row that fails the
   check", "counts nothing from a row that failed".
4. **Transfer rows, and rows in progress.** A row with `transfer: true` passes with a
   grade column of nothing, "T", "TR" or an unknown mark, and with `attempted` missing,
   null or "" (its credits are then 0); it counts as passed. The same marks on an
   ordinary row are a fault. An ordinary row with grade "" is in progress, exactly like
   one with no grade. Numbers as text ("3", "3.00", " 3.00 ") are accepted for
   `attempted`, `earned` and `points`. — "does not judge the grade column of transfer
   credit", "reads numbers the way a transcript prints them".
5. **Matching is by code, never by description.** ORI 100 described as "First Year
   Experience" and CIS 206 as "Bus Programming Languages" are "listed"; BIOL 127 is its
   own course, apart from BIO 127; a row coded XYZ 101 whose description is the exact
   title of a curriculum course is "none" and fills nothing; a row with the right code
   and a wrong or missing description is matched all the same; a code is matched whatever
   the letter case or spaces around its two parts ("eng" + "131", "ENG " + " 131", number
   131 as a number). — "matches by course code and never by title".
6. **An unmatched row fills nothing.** Rows for BIO 230 and XYZ 101 with an A pass the
   check, are marked "none", and add no credit to any block; MKT 410 is "elective" and
   fills an elective place; CIS 304 is "none". — "lets an unmatched row fill nothing".
7. **Lines that are not courses.** Rows carrying "Term GPA", "Transfer Term GPA", "Combined
   GPA", "Academic Standing" or "Transfer Totals" (in the prefix or the description, in
   any letter case, with their numbers) are thrown away: not among the rows that passed,
   not among the rows to fix, and counted as thrown away. `sample-b` with them and
   without them gives the same reading otherwise. A row that carries such a phrase but
   has a course code is kept and checked as a row (a course described "Academic Standing
   Seminar"); a real course is never thrown away (a description such as "Academic
   Writing" stays). — "throws away the GPA, standing and transfer-totals lines".
8. **An answer that is no answer, and what an answer may not bring in.** null, text, a
   number, a list, an object without `rows`, `rows` that is not a list: refused with an
   error that says the transcript could not be read; nothing is returned to count. An
   empty list of rows is a reading with no rows. Ten thousand rows, and ten thousand
   non-objects, are read row by row without failing. Fields the shape does not name are
   ignored and appear nowhere in the reading: an answer with `"student": { "name", "id" }`
   and a row with an extra `"ssn"` field give a reading that holds neither. Keys such as
   `"__proto__"`, `"constructor"` and `"prototype"`, at the top or in a row, change
   nothing outside the reading (`Object.prototype` is as before) and each row is checked
   on its own named fields. — "refuses an answer that is not a list of rows", "brings in
   nothing the shape does not name".
9. **`sample-b` end to end.** The reading and the placement are those worked out by hand
   under "The two made-up transcripts": 23 done, 6 in progress, 92 left with no legacy
   answer; 26, 6 and 89 with Yes; the rows said to count nothing count nothing; CIS 205
   counts once; BIOL 127 counts as its own course. — "reads the second made-up
   transcript".
10. **Repeats and order.** The same row twice in one term, and the same course in two
    terms, count once (F03's rule for repeats). Rows out of term order are read in the
    order given; nothing assumes the order is by date. — "counts a repeated course once,
    in any order".
11. **Hostile text does no harm here.** A description or term holding markup, 10,000
    characters or control characters passes or fails the check on its merits and comes
    back as plain text, unchanged; the code never builds a course code from a
    description. — "treats text fields as text".
12. **The PDFs are what the answers say.** Each PDF in `synthetic/transcripts/` is exactly
    what the script writes from its answer file (byte for byte; written twice, the bytes
    are the same: no date or other varying field), is a well-formed PDF (its
    cross-reference offsets point at its objects), and its text, kept uncompressed so it
    can be read without a dependency, holds: the term headings as printed; for each
    course row its prefix, number, description, attempted, earned, grade and points; a
    Term GPA, Transfer Term GPA and Combined GPA line and an "Academic Standing" line per
    term; for `sample-b` a "Transfer Credit" section with its "Transfer Totals" line and
    rows under ASU course codes. — "keeps each made-up PDF in step with its answer", "lays
    the made-up transcripts out like the real one"; evaluator (both files open in a real
    PDF viewer).
13. **Synthetic only.** Every PDF page and answer file says it is synthetic; the student
    is "Sample Student" with ID 000000000; the PDF's own details (title, author,
    producer) say only "PathCheck synthetic"; no file under `synthetic/` or `tests/` holds
    anything else that looks like a person's name, ID, address or birth date. — "holds no
    real student data"; reviewer.
14. **No Gemini, no network.** Nothing in `src/reader.ts` or the script makes a request or
    reads a key; the F06 scans still pass (`src/reader.ts` holds no course code, title or
    scale letter: the scale is the curriculum's). — the scans; "reaches nothing outside".
15. **F10 is not marked passing.** In `features.json`, F10 has `passes: false`, its tests
    named, and evidence that says the on-screen parts wait for F11; this file's "Result"
    starts with BLOCKED; `node scripts/status.mjs` names F11 as next.
    `docs/sprints/_carried-forward.md` has, for F11: the two on-screen checks that finish
    F10 (an invalid row is shown for the student to fix and is not counted until fixed;
    the localhost upload takes the two synthetic PDFs and nothing else is read); how a
    fixed row is checked again (`readRows`); that a transfer row is labelled "Transfer
    credit"; that an ordinary row with no grade is shown "In progress" for the student to
    confirm. For F21: the answer shape the function must return, and the real wording of
    the transfer totals to confirm. For F14 and F15: `sample-a`'s in-progress term is
    Fall 2026 (the design's), and how a summer term is printed is still to be asked. The
    F10 notes that are dealt with are removed. `docs/decision-log.md` has the "Decided
    here" entries. — the files; the command; reviewer.
16. **`npm run check` passes.** — the command.
