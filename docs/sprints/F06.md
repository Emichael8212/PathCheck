## What the student gets
Opening PathCheck shows the start page of the approved design: the name, two big choices
("Check my courses" and "See what I have left"), a short demo of how it works, and nothing
to fill in first. Each choice opens its flow's page. This is the first real screen of the
app; the flows themselves are the next features.

## User-visible change
Yes.

## What is built
- **The app shell.** `index.html` loads `src/main.ts`. One page with three addresses:
  `#/` (Start), `#/check` (Check my courses) and `#/left` (See what I have left). Any other
  address shows Start. The browser's Back and Forward buttons work.
- **Shared pieces**, as in the design: the top bar (wordmark, the two navigation links,
  "Not an official degree audit.") and the footer.
- **The Start page**, as in the design: the intro with the major dropdown, the panel with
  the two choices, and "See it work" with its four-step demo.
- **The two flow pages, empty for now.** `#/check` and `#/left` show the top bar, the
  flow's name as the page heading, and the footer: nothing else, and no "coming soon".
  F07 (Check my courses) and F11 (See what I have left) replace them.
- `src/style.css`: the approved design's stylesheet (a copy of `mockups/style.css` without
  the few rules only the mockups need; the two fonts stay where they are and are not
  duplicated). `mockups/` is not changed: it stays
  the M0 reference.

## Decided here (recorded in `docs/decision-log.md`)
- **No UI framework.** Plain TypeScript: each page is a function that returns HTML text, as
  in the approved mockups, plus small functions that wire up what moves. No new
  dependency. Undo: add a small framework when a screen needs it.
- **One page with `#/…` addresses**, so that what the student entered stays in memory when
  moving between the two flows, and a static host needs no extra rules.
- **Examples come from the curriculum.** The design's example answers (MGT 321, BIO 230 and
  the demo's made-up student) are named by course code, and only by code, in one file,
  `src/examples.json`, which only the Start page reads. Titles, credits, block names and
  totals are never written there or in code: they are looked up in, or worked out from,
  the curriculum, and tests check that what each example says is true.
- **Sentences and defaults that later screens reuse live in one place each:** the
  condition, the pace caveat, the privacy sentence and "Doesn't count toward CIS — not in
  the CIS curriculum" in `src/wording.ts` (F08 uses the same constants); the 3 credits of a
  course PathCheck doesn't know in `src/credits.ts` (owner answer, 2026-11-16; F09 uses the
  same constant).
- **"Report a mistake"** is an email link to a placeholder address until the owner gives
  the real one (brief §12), as in the mockups.
- **The drop zone does not take files yet.** Until F11, "Browse files" and a file dropped
  on the Start page both open the "See what I have left" page; the file is not read and
  nothing leaves the browser.
- **The demo's pace line** ("On pace for Spring 2029") is example text for the made-up
  student until F14 can work it out; F14 must check it, also against the sequence, or
  change it (carried forward).

## Differences from the approved screenshots (listed in the pull request, and in DESIGN.md)

  "Curriculum last reviewed: Nov 2026"". The curriculum file has no review date and none

- **No "Mockup: opens synthetic student results." line** under "Browse files": it was a

## Acceptance checks
Tests are in `tests/start.test.ts` (text and markup, no browser) unless another is named.
"Evaluator" means checked in a real browser against the screenshots.

1. **Two big choices, nothing to fill in first.** Opening `/` shows the Start page with
   two choices, "Check my courses" and "See what I have left", each a heading with its own
   link. The Start page has no `<input>`, `<textarea>` or `<form>` and no `required`
   attribute; its only `<select>` is the major dropdown, with its one value selected.
   — "shows the two choices and nothing to fill in"; evaluator.
2. **The owner's wording.** Every text of the Start page equals the approved mockup's
   (`mockups/data.js`, `start`), apart from the mockup note: the badge "Before
   registration. Before you pay."; the headline "Does it count toward your degree?" /
   "Check before you select your classes."; "Know what counts. See what's left. Make room
   for what matters."; the labels, titles and descriptions of the two choices;
   "~30 seconds · No transcript needed"; "Drag & drop your transcript PDF here", "or",
   "Browse files"; the privacy sentence "Your PDF is read, then deleted. Only your result
   stays in this browser." next to the upload control; the demo's label, heading, line,
   three-step list and four captions. The top bar says "Not an official degree audit.".
   — "keeps the owner's wording".
3. **Name, affiliation, colors.** "PathCheck" is in the top bar and "Not affiliated with
   Alabama State University" in the footer, on all three pages. No page has an `<img>` or
   a logo. In `src/style.css` every color value sits in a token (a custom property in
   `:root`), every color token has a dark-mode value, rules use only `var(--…)` for color, and
   the token names and values equal those of `mockups/style.css` in light, dark and
   print. — "shows the name and that it is not affiliated", "uses the design's color
   tokens and nothing else"; evaluator.
4. **No sign-in, account or advisor.** The Start page, the top bar and the footer contain
   no "sign in", "sign-in", "log in", "login", "password", "account" or "accounts" as a
   whole word, and no "advisor", in any letter case; no page contains "ask your advisor".
   — "has no sign-in, account or advisor screen".
5. **The major dropdown.** A labelled dropdown "Your major" with exactly one option,
   "B.S. Computer Information Systems", selected; no disabled option and no "coming soon".
   The option comes from the list of programs loaded from the curriculum data (given a
   list with a second made-up program, the page shows two options). — "lists only the
   majors the app has, one of them".
6. **Each choice opens its flow.** "Check my courses" (the button and the top-bar link)
   goes to `#/check`; "Browse files" and "What I have left" in the top bar go to `#/left`.
   Each flow page has the flow's name as its one `<h1>`, the top bar with that link marked
   as the current page, and the footer. The wordmark goes back to Start. An unknown
   address (`#/nothing`, `#`, empty) shows Start. — "opens each flow from its choice",
   "shows Start for an unknown address"; evaluator, including Back and Forward.
7. **Moving between pages is announced and usable by keyboard.** After a page change the
   browser tab's title names the page ("PathCheck", "Check my courses — PathCheck", "See
   what I have left — PathCheck"), keyboard focus is on the new page's heading, and the
   page is scrolled to the top. Every link and control can be reached and used with the
   keyboard alone, with a visible focus outline. — "names each page in the tab title";
   evaluator (focus, scroll, keyboard).
8. **The example answer is true.** The example card shows MGT 321 with its title, credits
   and block from the curriculum, as "Counts toward CIS — Business core" followed by
   "unless you've already passed it or filled this slot", with the outlined "Counts" mark,
   never the filled "Done" mark (owner answer g). A "Counts" answer never appears on the
   page without that condition. A test checks against the curriculum that the example
   course is a required course of the block named. — "shows one example answer, with its
   condition", "takes the example's facts from the curriculum".
9. **The demo.** "See it work" has four frames, a pause/play button, four step buttons and
   a caption "n/4 …". Frames: typing "mgt 3" with MGT 321 suggested; the MGT 321 answer
   with its condition and the "Counts" mark; BIO 230 added as "Doesn't count toward CIS —
   not in the CIS curriculum" with its credits struck through; a transcript file with the
   made-up student's credits left, the bar, the pace line and "Credits only — course order
   may add semesters." Tests check that:
   - the suggested course is a curriculum course whose code starts with what was typed,
     shown with its curriculum title;
   - BIO 230 is in no curriculum list and is not an elective by the rule; its sentence is
     the shared constant and its "3 cr" the shared unknown-course default;
   - the credits left and the bar's two parts are what `placeCourses` gives for the
     made-up student's courses (81 left: 27 done, 13 in progress), and that student's
     history-or-literature sequence is still needed, with the Social sciences pick open,
     so the frame does not suggest a finished sequence;
   - the pace line never appears without the caveat.
   — "has the four-step demo", "says only true things in the demo".
10. **The demo moves, stops and can be operated.** It advances by itself every 3.6 seconds
    and wraps from 4 to 1; the round button pauses and plays, and its label says which; a
    step button jumps to that step and stops; with Reduce Motion on it does not start by
    itself. The caption is read out only when the student moves the demo. The pause/play
    button and the four step buttons have accessible names, can be reached by keyboard
    and show the focus outline; the frames are hidden from assistive technology and hold
    nothing that can take focus. Leaving the Start page stops the timer; coming back
    starts the demo again from step 1. — "steps through the four frames and wraps",
    "pauses, plays and jumps", "stays still under Reduce Motion", "stops when the student
    leaves the page", "keeps nothing focusable inside the hidden frames"; evaluator
    (keyboard; Reduce Motion emulated).
11. **A dropped file is never opened or read.** A file dropped anywhere on any of the
    three pages does not make the browser open it. On Start it opens the "See what I have
    left" page; on the flow pages it does nothing. The file is not read. With the built
    site (`vite preview`), the page makes no request after it has loaded and none to
    another origin at any time (the fonts are local). Dragged text is left alone (added in
    QA). — "does not read a dropped file" (for a drag that carries files the default
    action of `dragover` and `drop` is prevented; only the kind of thing dragged is asked,
    nothing of the file is read); evaluator (drop a PDF; watch the network).
12. **The footer.** One line: "Not an official degree audit." (bold), "Report a mistake"
    (an email link) and, at the right, "Not affiliated with Alabama State University".
    With today's data (no review date) there is no "Curriculum last reviewed" text
    anywhere, and "Nov 2026" appears nowhere. Given a test curriculum dated 2026-01-15 the
    footer reads "Curriculum last reviewed: Jan 2026"; 2026-01-01 and 2026-12-31 read
    "Jan 2026" and "Dec 2026" in every time zone (tested in America/Chicago and
    Pacific/Kiritimati). The text is never "Invalid Date" or "NaN": the loader refuses a
    malformed date. — "leaves the last-reviewed line out while there is no date", "shows
    the month and year of a review date in any time zone".
13. **It looks like the approved design.** At 1440 and 375 wide, in light and in dark, the
    Start page matches `docs/design/screens/start-*-*.png`, and each demo step matches
    `start-demo-step2…4-light-*.png`, apart from the two listed differences. At 375
    nothing is hidden, cut off or overlapping, the page does not scroll sideways, and the
    two navigation links sit on a second row of the top bar. Contrast meets WCAG AA in
    light and dark (4.5:1 for text; 3:1 for large text, controls and the focus outline).
    None of the banned elements of brief §8 appears; the elements the owner kept (the
    pill badge, the upload icon in a circle, the small uppercase labels, the numbered
    chips, the indigo main button, the pill-shaped navigation links: answer f) are not
    counted as banned. — evaluator, with screenshots.
14. **No curriculum fact in the app's source.** The scan "keeps curriculum facts out of
    the code" now reads every file in `src/` (TypeScript, CSS, JSON), `index.html` and
    `public/` if it exists, and also fails on any course title of the curriculum (exact,
    case-sensitive). In CSS only the course-code and title parts apply (a size such as
    `42px` is not a credit total). The scan "has no CIS 304 …" reads the same files.
    `src/examples.json` is the one exception, for course codes only: a test asserts its
    exact shape, that every text value in it is a course code and nothing else, that it
    holds no number, and that CIS 304 and CIS 415 are not in it; and that the Start page
    module is the only file in `src/` that imports it. — the two scans in
    `tests/curriculum.test.ts`; "names only course codes in the examples file", "lets only
    the Start page read the examples".
15. **The built site works.** `npm run check` passes (lint, typecheck, tests, build).
    `npx vite preview` of the build: the Start page loads with the major's name (which
    comes from the curriculum file bundled from `docs/`), both fonts, and no console error

16. **Records.** `docs/decision-log.md` has the "Decided here" entries.
