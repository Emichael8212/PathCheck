# F03 — Which transcript rows count: grades, W and I, repeats, in progress, and transfer/AP/CLEP

## What the student gets
Nothing visible yet. This is the rule that decides, for every course on a transcript,
whether it is passed, in progress, must be repeated, or earned no credit. The checklist,
the "does it count" answers with a transcript, the pace and the plan all read it.

## User-visible change
No. Visual design and Clarity are N/A. Every check below names its automated test in
`tests/transcript.test.ts`, run with `npm test`, using made-up rows only.

## What is built
- `src/transcript.ts`:
  - `TranscriptRow`: one course line as read from a transcript: course code, term as
    printed, credits attempted, the grade as printed (`null` when the column is empty), and
    whether the line is under transfer credit (transfer, AP and CLEP are all listed that
    way).
  - `rowStanding(row, grades)`: what one row is worth on its own.
  - `courseStandings(rows, grades)`: one result per course code, after repeats.
- The grade scale comes from the curriculum data (`Grades`: letters best first, the lowest
  that counts, the marks that never count). No grade letter is written in `src/`.
- A standing is one of five words:
  - **passed** — a grade at or above the lowest that counts, or transfer credit with no
    grade shown;
  - **in progress** — no grade yet: assumed to pass, but not passed. It is distinct from
    every other standing and is the only one that means "assumed to pass, not yet passed";
  - **must repeat** — a letter grade below the lowest that counts;
  - **no credit** — a mark that never counts (W, I);
  - **unrecognised** — the grade column holds something that is not on the scale (see
    "Decided here"). It never passes.
- **"Passed" is not "counts toward CIS".** A standing says only what the row earned by its
  grade (or that it is transfer credit with no grade shown). Whether the course is under an
  ASU course code and in the curriculum is decided when rows are matched by code (F10), and
  which requirement it fills, if any, when courses are placed (F04). The "when shown under
  an ASU course code" half of this feature's step 5 is proved there: a row whose code is
  not a course code never reaches the checklist (F10), and a course outside the curriculum
  never fills a requirement (F04).
- **One place decides whether a grade is on the scale.** F10 uses `rowStanding` for that: a
  row that is "unrecognised" is the invalid row F10 and F11 show for the student to fix.
  "Unrecognised" is never a checklist status (F13).
- Not here: checking that a row is well-formed (F10), any wording on screen (F11, F13).
  The feature's step 4 says an in-progress row is "shown as In progress" and "never marked
  Done"; those two are checked on screen in F11 (step 4) and F13 (step 2). Here the check
  is that in progress is never "passed".

## Decided here (recorded in `docs/decision-log.md`)
- **A grade that is not on the scale never passes, and is "unrecognised".** The owner said
  only A, B, C, D, F exist, with no plus/minus and no pass-type grades, so such a mark
  should not appear. If one does (a misread, or something unforeseen) it is not "C or
  better", so it does not pass; it is not called "must repeat" (that would be a claim); and
  it is reported so the review step can ask the student to fix it.
- **A transfer row with a mark that is not on the scale is treated the same way** for now.
  This can only under-count. What a real transfer row's grade column shows is an open
  question to the owner (asked 2026-11-16, recorded in the decision log); it must be
  answered before the real reader is built (F21, M2). Until then no made-up transcript
  invents a transfer mark.
- **When a course has several rows and none passes**, its standing is the first of these
  that applies: in progress, unrecognised, must repeat, no credit. In progress comes first
  because the brief says to assume the course will be passed and not to schedule it again.
  "Must repeat" is shown only when no row leaves the outcome open; it outranks "no credit"
  because the flag belongs to the below-C grade and a later W does not remove it.

## Acceptance checks
1. **Letters only; C or better passes.** A row graded A, B or C is "passed". A row graded D
   or F is "must repeat". The scale is read from the curriculum data: the same rows judged
   against a test-only scale whose lowest counting grade is B give C → "must repeat". A
   test confirms `src/transcript.ts` contains no grade letter of its own. — "passes C or
   better", "flags D and F as must repeat", "reads the scale it is given".
2. **No plus/minus or pass-type grades.** "B+", "C-", "A-", "P", "S", "CR", "T", "C*",
   "C (R)" and "CC" are not on the scale: the row never passes and is "unrecognised", not
   "must repeat". — "does not pass a grade that is not on the scale".
3. **W and I.** A row marked W or I is "no credit", not "must repeat" and not "passed".
   — "gives no credit for W and I".
4. **How the grade is written.** Spaces around it and lower case are ignored: " c " is C,
   " w " is W, " i " is I, " d " is D. "No grade" is `null`, an empty string, or only
   spaces (and `undefined`, if untyped code passes it). With no grade, an ordinary row is
   "in progress" and a transfer row is "passed". — "reads a grade whatever its case and
   spacing", "treats an empty grade column as no grade".
5. **In progress.** A row with no grade, not under transfer credit, is "in progress", which
   is not "passed". A transfer row is never "in progress". Two rows of one course with no
   grade: "in progress". A transfer row with no grade plus an ordinary row with no grade:
   "passed". — "treats a row with no grade as in progress, not as passed".
6. **Repeats: the highest grade counts.** For one course with several rows: D then B is
   "passed", decided by the B; B then D is "passed", still by the B (a later, lower grade
   does not undo it); F, D, C is "passed" by the C; D then F is "must repeat", decided by
   the D; F then D likewise by the D. — "takes the highest grade of a repeated course".
7. **Repeats with a row in progress.** D earlier and no grade now: "in progress", and the
   result still lists the earlier row as "must repeat" (the checklist will say "Repeat; the
   earlier D doesn't count."). W earlier and no grade now: "in progress". C earlier and no
   grade now: "passed" (it is already passed). — "keeps a repeat in progress as in
   progress", "keeps a passed course as passed while it is retaken".
8. **Transfer, AP and CLEP.** A row under transfer credit with no grade is "passed" (no
   grade check). With a grade shown, the grade is checked like any other: C or better
   passes, D or F (including " d ") is "must repeat", W or I is "no credit", anything else
   is "unrecognised". — "passes transfer credit with no grade", "checks a transfer grade
   when one is shown".
9. **Never passes by accident.** For every ordered combination of one to three rows drawn
   from 22 kinds (A, B, C, D, F, W, I, no grade, "B+", "P", "TR", each as an ordinary row
   and as a transfer row):
   - the course is "passed" if and only if at least one row passes on its own;
   - it is "in progress" if and only if no row passes and at least one is in progress;
   - it is never "must repeat" while any row passes, is in progress or is unrecognised;
   - the standing is the same for every order of the same rows.
   — "never passes a course unless one of its rows passes".
10. **One result per course, and every row keeps its own result.** `courseStandings`
    returns one entry per course code, in the order the codes first appear, each with its
    standing, the row that decided it, and every row of the course with that row's own
    standing. The deciding row is, among the rows that have the course's standing, the one
    with the best grade on the scale; if they tie or have no grade on the scale, the first
    in transcript order. B and "B+" for one course: the course is "passed" by the B, and
    the "B+" row is still reported "unrecognised". Rows of different courses never affect
    each other; an empty transcript gives an empty list. — "gives one result per course",
    "keeps each row's own standing".
11. **Grouping by code.** Rows are grouped by course code however it is written, using the
    curriculum's `normalizeCode`: "ECO 251" graded D and "eco251" graded B are one course,
    "passed". The result carries the code in its normal form. A row whose code is not a
    course code is a programming error, because rows are checked before they get here
    (F10): `courseStandings` throws an error that names the code. — "groups rows by course
    code however it is written", "refuses a row whose code is not a course code".
12. **The decision log is true.** `docs/decision-log.md` has the three "Decided here"
    entries and a dated open question to the owner about what a transfer row's grade column
    shows, to be answered before F21. — reviewer; the file.
13. **Made-up data only.** The tests use invented rows; no real student's rows are in the
    repository. — the test file itself; reviewer.

## Out of scope
- Whether a course is in the curriculum, which requirement it fills, electives, legacy,
  credits counted toward a block (F04, F05).
- Checking that a row is well-formed: a bad code, missing credits (F10).
- Reading a PDF (F21) and the review screen (F11).
- Any wording shown to the student ("In progress", "must be repeated"): F11, F13.
