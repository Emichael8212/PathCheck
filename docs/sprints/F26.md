### 3. `docs/milestones/M3.md`, the record of the M3 check
As `docs/milestones/M2.md` is for M2: what M3 is; the owner's steps, each with what it
should show; what was seen; everything still open; every merged pull request of M3. The
owner's steps, in this order:
1. **The address.** The owner creates the mailbox and tells the agent the address. It
   will be readable by everyone, on the site and in the repository: a mailbox kept for
   PathCheck alone is wise.
2. **Build and publish**, as at M2, after the pull request with the address is merged
   (the site is still Private).
3. **"Report a mistake" reaches the mailbox.** On the private site the owner clicks the
   link on "Check my courses" with a course in the list, sends the email it opens, and
   finds it in the mailbox, with the page's lines in it.
4. **The handover guide's clicks, once** (carried forward from F25): the owner follows
   Step 2A of `docs/CURRICULUM-HANDOVER.md` with a later date up to the green check, says
   whether every label was as the guide writes it, and then **closes the pull request
   without merging and deletes its branch** (the review date stays 2026-11-15; the site
   is still Private, so that pull request's preview is not public).
5. **The final check** on the private site: both flows on a computer and on a phone, as at
   M2, with nothing in the browser's console from PathCheck's own files.
6. **Before the launch: the previews.** Today a Deploy Preview has the Gemini key and uses
   Cloudflare's test secret, so its bot check lets every caller through; the number of a
   browser is whatever the caller sends; and the previews count their uploads in the
   same store as the real site (`getStore`, the project's own, in
   `netlify/functions/read-transcript.mts`). That was safe while only the owner could
   open a preview. On a public project a preview's address can be guessed (the
   repository is public). Someone could then spend the month's $5 there, and the real
   site would refuse every student until the next month. The cost is capped; the service
   is not. One of these closes it, and **the choice is the owner's**:
   - **(1) Previews stay private.** Netlify's documentation says "Previews stay private
     unless you change the preview visibility setting", and does not say whether the Free
     plan has that setting. The owner looks at Netlify's visibility form at the launch:
     if it lets production be public while previews stay private, that is chosen, and
     nothing else is needed.
   - **(2) No Gemini key on previews** (the agent's recommendation if (1) is not
     offered): the owner removes the Deploy Previews value of `GEMINI_API_KEY`. A
     preview then refuses every upload at its key check, before anything is counted or
     spent, with "Upload isn’t available right now — try again tomorrow". The price: a
     later change to the reader cannot be tried on a preview unless the owner puts the
     value back for a while, and that preview is then public.
   - **(3) No previews at all:** Netlify can stop building Deploy Previews. The owner
     then has no preview to look at in a pull request.
   - **(4) A change of the code:** a preview without the owner's own Turnstile secret
     refuses uploads (no test secret). It ends uploads on previews for good and is a new
     pull request with its tests.
   Also read by the owner there: "Untrusted deploys policy" (Project configuration >
   Developer settings > Continuous deployment), which Netlify's documentation says is
   "Require approval" by default for a public repository, so that a pull request from a
   stranger's copy is not built with the secrets before the owner approves it.
7. **Launch:** the owner makes the site public (Netlify's visibility) and, if they wish,
   unlocks auto publishing; then a later merge publishes by itself. Neither is done by
   the agent.
8. **The public site:** in a browser that is not logged in to Netlify, on a computer and
   on a phone: Start opens; "Check my courses" answers a course; a made-up transcript is
   read; the fourth upload of a day is refused; "Report a mistake" opens an email to the
   address. And a screenshot of Netlify's function log after that upload.
