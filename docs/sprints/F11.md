## What the student gets
On "See what I have left" the student chooses or drops their unofficial transcript PDF,
having read one sentence about what happens to it. PathCheck then shows what it read, term
by term: each course with its grade, or "In progress", or "Transfer credit", and which rows
do not count. A row that was misread can be corrected, and a row PathCheck could not make
sense of is marked for fixing. "Continue" takes the reviewed rows on.

At M1 this runs on localhost with the two made-up transcripts only: nothing is sent
anywhere.

## User-visible change
Yes.

## What is built
- **Upload**, on `#/left` and from Start: the drop zone and a "Browse files" button that
  opens the file picker, with the privacy sentence beside them ("Your PDF is read, then
  deleted. Only your result stays in this browser."). A PDF is the only input; no
  transcript can be typed in.
- **The M1 reader** (`src/upload.ts`): the chosen file is looked at in the browser. A file
  over 10 MB is refused before it is read; a file that does not begin with `%PDF-` is not
  a PDF, whatever its name. A PDF is recognised as one of the two made-up transcripts by
  its length and a fingerprint worked out by plain code (listed in
  `synthetic/transcripts/manifest.json`, written by the script), so it also works on a
  phone that opens the development server over the network. Its prepared answer goes
  through `readRows` (F10). Any other file is refused with a sentence; nothing of it is
  kept or sent. The made-up answers are loaded only on a development server.
- **The review step** (`src/review.ts`), built from the pieces of the approved design (the
  course rows, the marks, the buttons, the colors):
  - rows grouped under their term headings, in the order read; each shows the course
    code, the description as printed, the credits, and its state in words;
  - a row that needs fixing shows what is wrong with it;
  - every row has "Edit": term, prefix, number, credits, grade (a list: no grade yet, or
    a letter or mark of the curriculum's scale) and "Transfer credit" (a tick box). "Save"
    checks the row again with `readRows`; "Cancel" leaves it;
  - every row has "Not on my transcript": the row is left out (struck through, counting
    nothing) and "Put back" undoes it. A reader can invent a course; the student must be
    able to refuse it;
  - a line that is not a row at all cannot be edited (that would be typing a course in):
    it is shown as "This line could not be read" and counts nothing;
  - "Continue", and "Use another transcript" to start again (it forgets the corrections,
    and says so).
- The transcript is kept in memory for the visit, like the course list.

## How a row is shown
| The row | Shown as |
|---|---|
| Passed with a grade of C or better | the grade, and "Passed" |
| No grade yet | "In progress", and under it "No grade was read. Edit this row if the course already has one." |
| In the transfer-credit section | "Transfer credit" (its grade column is shown as printed and not judged), and "Passed" |
| Below C (D or F) | the grade, and "Doesn't count — below C" |
| W or I | the mark, and "Doesn't count — <mark>" |
| Its code is in no curriculum list and matches no rule | its state as above, and "Not in the CIS curriculum" |
| CIS 304 or CIS 415 | its state as above, and "<code> isn't in the current CIS curriculum" (the owner's words) |
| Left out by the student | struck through, "Not on my transcript", with "Put back" |
| Failed the check | "Needs fixing", and what: the course code, the credits, the grade, the term, or whether it is transfer credit; a line that is not a row at all: "This line could not be read" |

A grade is shown trimmed and in capitals. "Passed" here is about the grade only. Whether a course counts toward the degree is the
checklist's to say (F13): the review step never says "Counts".

## Decided here (recorded in `docs/decision-log.md`)
- **The review step is a new screen** made of the approved design's pieces; its layout and
  its words (the table above, the headings, the buttons, the sentences below) are the
  agent's and are listed in the pull request for the owner, who was told before it was
  built.
- **Continuing with rows still to fix is allowed.** They count nothing, and a line above
  "Continue" says how many there are. (The cautious direction: nothing unread is counted.)
- **Every row can be edited**, not only the ones that failed: a misread grade, code or
  term can pass the check. **Any row can be left out** ("Not on my transcript") and put
  back. No row can be added: the PDF is the only input.
- **A second transcript replaces the first**: "Use another transcript" forgets the rows
  and the corrections, and the line beside it says so. A file dropped on the page during
  a review is not opened and not read.
- **After "Continue"**, until the checklist is built (F13), the page shows its heading
  and one line: how many rows are taken on and how many are left out. F11's step 5
  ("Continuing uses the reviewed rows, including the student's fixes") is tested where
  the rows are handed on, and is checked on screen with F13: so **F11 stays not passing
  until F13** (BLOCKED, as F05, F07 and F10 were), while **F10 is finished by this pull
  request**.
- **The legacy question is not asked in the review step**: the step says nothing about
  what counts toward the degree. It is asked where that is shown (F12, F13). The F05 plan
  is updated accordingly.
- **Refusals at M1** (agent's wording): for a PDF that is not one of the two made-up
  transcripts, "PathCheck can only read its two made-up transcripts for now. Nothing from
  this file was kept or sent."; for a file that is not a PDF, "That file is not a PDF.
  Choose the unofficial transcript PDF from the portal."; for a file over 10 MB, "That
  file is too large to be a transcript. Nothing from it was read."; outside a development
  server, the brief's "Upload isn't available right now — try again tomorrow".
- **The fingerprint is plain code** (the file's length and two simple checksums), not a
  browser security feature: it only tells the two made-up PDFs from other files, and it
  works where the browser offers no cryptography (a phone on the local network).
- **On Start, "Browse files" opens the file picker** through a file control made at that
  moment, so the page still has nothing to fill in; the chosen or dropped PDF is carried
  to `#/left`.

## Acceptance checks
Tests are in `tests/upload.test.ts` and `tests/review.test.ts` (rules and the pages' text)
and `tests/left-page.test.ts` (the page in a simulated browser). "Evaluator" means checked
in a real browser on the development server at 1440 and 375, light and dark.

1. **The PDF is the only input.** `#/left` before an upload shows the drop zone, "Browse
   files" and the privacy sentence, and no field in which a course or a grade could be
   typed. — `review` "offers the PDF as the only way in"; evaluator.
2. **The sentence comes first.** "Your PDF is read, then deleted. Only your result stays in
   this browser." is beside the upload control on `#/left` and on Start, before anything
   is chosen. — "shows the privacy sentence with the upload control".
3. **Choosing and dropping.** "Browse files" opens the file picker on `#/left` and on
   Start; choosing `sample-a.pdf` there, or dropping it on the drop zone, leads to the
   review step on `#/left`, with the keyboard on its heading. A drop elsewhere on the page
   is still never opened by the browser. Choosing the same file twice in a row works (the
   file control is cleared after each choice). After a refusal the keyboard is back on
   "Browse files" and the sentence is read out. During a review a dropped file is not
   opened and not read, and a polite status says "To use another transcript, choose “Use
   another transcript” first." (agent's wording). — `left-page` "reviews a chosen transcript", "takes a transcript
   dropped on Start", "takes the same file twice"; evaluator (real file picker; real drag
   and drop).
4. **Only the two made-up transcripts, and nothing leaves the browser.** `sample-a.pdf`
   and `sample-b.pdf` are recognised by their fingerprints; the same PDF with one byte
   changed and another PDF get the made-up-transcripts sentence; a text file renamed
   `.pdf`, an image and an empty file get the not-a-PDF sentence (it goes by the file's
   first bytes, `%PDF-`, not its name or type); a file over 10 MB is refused before it is
   read, with its own sentence. The page stays ready for another file. No request is made
   when a file is chosen. Recognising works without the browser's cryptography (tested
   with it taken away). The manifest's fingerprints are those of the committed PDFs. — `upload` "recognises only the made-up transcripts", "keeps the fingerprints in
   step with the PDFs", "sends nothing"; evaluator (network watched).
5. **What was read, term by term.** For `sample-a`: the headings "Fall 2025", "Spr 2026",
   "Fall 2026" in that order, each with its rows in the order read; every row shows its
   code, its printed description, its credits and its state. For `sample-b`: "Transfer
   Credit" first, then its three terms. The GPA, standing and totals lines are nowhere. An
   answer with no rows at all shows "No courses were read from this transcript.", with
   "Use another transcript" and without "Continue". — `review` "lists the rows under
   their terms", "never shows the lines that are not courses", "says when nothing was
   read".
6. **The states, in words.** In `sample-b`: ENG 131, MAT 137 and HIS 131 show "Transfer
   credit" and "Passed", with "T", "TR" and "AP" as printed; ORI 100 "A" "Passed";
   BIO 127 "Doesn't count — W"; CIS 205 (Fall 2024) "Doesn't count — below C"; CIS 206

   CIS 206 and ECO 251 (Fall 2025) "In progress", each with the line asking to edit the
   row if the course already has a grade. A row for CIS 304 or CIS 415 says "<code> isn't
   in the current CIS curriculum". A grade read as " b " is shown "B". No row says
   "Counts", and none is marked with the "Counts" or "Done" mark. — `review` "says how each row stands", "never
   says a row counts".
7. **A row that needs fixing.** A reader's answer with a faulty row (a code that is not a
   code; a grade "B+"; credits "abc"; a transfer flag that is not yes or no; a line that
   is not a row) shows that row with "Needs fixing" and what is wrong; it counts nothing;
   the line above "Continue" says how many rows still need fixing. (This finishes F10
   step 1.) — `review` "shows a faulty row and what is wrong with it"; `left-page`
   "counts nothing from a row that still needs fixing"; evaluator, with a prepared faulty
   answer.
8. **Fixing a misread row.** "Edit" on a row opens its fields with what was read; changing
   the grade "B+" to "B" and saving makes the row "Passed" and takes it off the list of
   rows to fix; a row whose term was not read is fixed by typing the term; changing a
   passed row's code or grade, or ticking "Transfer credit", changes how it is shown; a
   correction that is itself faulty (a code "MGT 32") keeps the row as "Needs fixing"
   with the new reason; "Cancel" changes nothing. The grade list holds exactly the
   curriculum's scale and marks, and "no grade yet". "Not on my transcript" leaves a row
   out: it is struck through, counts nothing and is not handed on; "Put back" hands it on
   again. A line that could not be read has no "Edit". — `left-page` "fixes a misread
   row", "fixes a row whose term was not read", "keeps a row to fix when the correction
   is faulty", "cancels an edit", "leaves out a row that is not on the transcript";

9. **Keyboard and screen reader.** Every control is reachable and usable with the
