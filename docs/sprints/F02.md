# F02 — Curriculum loaded as data: the one B.S. CIS curriculum (121 credits), stored so other majors can be added later

Milestone: M1 · Branch: `feat/F02-curriculum-data` · Brief sections: §3, §5, §6 · Owner
answers: 2026-11-15 "answers on PR #1" (titles, grades, sequence), "Answers to the nine

## What the student gets
Nothing visible yet. Every later feature (does it count, what's left, the plan) reads the
CIS curriculum from one checked data file instead of from code, so the answers can only be
as right as that file, and the file cannot drift from the brief without a test failing.

## User-visible change
No. Visual design and Clarity are N/A. Every check below names its automated test in
`tests/curriculum.test.ts`, run with `npm test`.

## What is built
- `src/curriculum.ts`: types for the curriculum, `loadCurriculum(data)` which checks a raw
  data object and turns it into the model the app uses, the loaded `curriculum`, and
  `programs`, the list of majors (one entry).
- The model keeps what later features need and nothing else: blocks with required courses
  and "choose N" groups, the elective rule, the legacy-only electives, the sequence
  alternatives and core blocks, the grade scale, the last-reviewed date. Course codes are
  held as "MGT 321" (the data file writes "MGT-321").
- `findCourse(curriculum, code)` returns every place a code is listed, as a list that is
  empty when the code is not listed. Each place gives where it is (a block's required
  list, a block's pick group, the named electives, or the legacy-only electives), the
  block id where there is one, which pick group of the block it is (a block can have two),
  and the course's title and credits from the data file.
- The loaded model is frozen: no code can change the curriculum, or a look-up result, at
  runtime.
- No rule about *using* the curriculum is decided here: grades (F03), placing courses and
  the elective rule (F04), legacy (F05). F02 only loads and checks.
- **One place for data tests.** The `curriculum data` tests in `tests/setup.test.ts` move
  into `tests/curriculum.test.ts`, rewritten against the loaded model (and the raw file for
  the key scans), and that block is deleted from `setup.test.ts`. Its `features.json` tests
  stay.
- **Academic facts stay out of code.** A later rule that names a course, such as "MGT 462
  in the final semester" (brief §4, built in F16), is added to the data file as a field and
  to the loader then. It is not written into `src/`, and the scan in check 1 gets no
  exception for it.

## Acceptance checks
1. **Read from the data file.** `curriculum` is built by `loadCurriculum` from
   `docs/curriculum/provisional-current.json`. A test reads every TypeScript file in `src/`
   and fails if it finds (a) text shaped like a course code
   (`\b[A-Z]{2,4}[ -]?\d{3}\b`), (b) any block `name` from the data file, matched exactly
   and case-sensitively, or (c) 121 or 42 as whole numbers (`\b121\b`, `\b42\b`). — "builds the curriculum from the data file", "keeps curriculum facts
   out of the code".
2. **One major, from data.** `programs` has exactly one entry. Its name is the data file's
   `program` field, "B.S. Computer Information Systems", and it carries the loaded
   curriculum. The list is what the major dropdown will read (F06); it has no "coming soon"
   or disabled entry. A made-up program, written as a fixture under `tests/` with fake
   codes and its own totals (not 121), loads through the same `loadCurriculum` with no
   change to it. The fixture is never added to `programs` or shipped. — "lists exactly one
   major, named by the data file", "loads a made-up second program through the same loader".
3. **Blocks match brief §5 exactly.** Eight blocks with the brief's names and credits, in
   the brief's order: Orientation 1, Composition 6, Humanities 12, Social sciences 12,
   Science & math 11, Pre-professional 19, Business core 27, Major (CIS) 24; plus CIS
   electives at 9 credits and 3 courses. Required courses and each pick group's courses
   match the brief as sets (order ignored). The expected table is written out in the test
   from the brief, not derived from the file. — "matches the table in brief section 5".
4. **121.** Block credits plus elective credits equal 121, and equal `degreeCredits`; in
   each block, required credits plus `choose` × the pick group's course credits, for each
   pick group, equal the block's credits; no
   course is listed twice across the blocks and the named electives. — "adds up to 121",
   "lists each course once".
5. **Elective rule and legacy list as data.** FIN 201 Personal Finance; 300–499 level MGT,
   FIN, CIS, MKT, ACT, ECO at 3 credits each; "not already required" kept as a flag; the
   four legacy-only courses with the owner's titles, 3 credits each. (How they are applied
   is F04 and F05.) `lastReviewed` is carried into the model unchanged (`null` today).
   — "carries the elective rule and the legacy-only courses", "carries the last-reviewed date".
6. **Sequence and grades as data.** The history (HIS 131 + HIS 132) and literature
   (ENG 209 + ENG 210) alternatives, adding no credits. The core blocks are Orientation,
   Composition, Humanities, Social sciences and Science & math, totalling 42 credits, which
   equals `coreCredits`. HIS 131 and ENG 209 are required; HIS 132 is in the Social
   sciences pick and ENG 210 is in the Humanities pick. Grades: letters A, B, C, D, F; C is
   the lowest that counts; W and I never count. (Applied in F03 and F04.) — "carries the
   sequence alternatives inside the 42 core hours", "carries the grade scale".
7. **Removed entries stay removed.** A test fails if any key or text value in the data
   file (apart from `electives.subjectRule.exceptCourses`, which must be exactly CIS-304
   and CIS-415: check 14), or any text in a TypeScript file in `src/`, matches
   `/CIS[- ]?304|CIS[- ]?415|\breplacement|\bold(er)?[ _-]?codes?\b|\bformerly\b|\bsupersed|not[- ]?offered|nonOffer|\bhistorical\b|\bunresolved\b/i`.
   ("legacy" and "history" stay allowed: the legacy-only electives and the history sequence
   are real.) A test confirms the pattern does not match ordinary code such as
   `code.replace(` or `placeholder`. `findCourse` returns nothing for CIS 304 and CIS 415. — "has no CIS 304,
   CIS 415, replacement, older-code or not-offered entry".
8. **No catalog year.** A recursive scan of every key in the raw data file and in the
   loaded model finds no key matching `/catalog|startYear|start_year|year/i`. (The source
   descriptions mention 2019–2021 and 2025–2027; that is text, not a key, and is allowed.)
   — "has no catalog-year or start-year field".
9. **Not checked.** No key or text in the data file, and no key or text in the loaded
   model, matches `/\bGPA\b|residen|Nelson|Denny|proficiency|comprehensive exam|competency/i`.
   "Not shown" is checked on rendered pages by the screen features (F06 onward) and by the
   evaluator in the browser. — "says nothing about GPA, residency or the suspended exams".
10. **The loader refuses a broken file.** Each of these, applied to a copy of the data,
    makes `loadCurriculum` throw an error whose message contains the path or id of the bad
    item (for example `blocks[2]`, `humanities`, `MGT-321`, `catalogYear`); each test checks
    for that text. One test per case, named "refuses a data file …":
    - a different `schemaVersion`;
    - a missing required field. Every field of schema version 2 is required;
      `lastReviewed` must be present and may be `null`. The test removes each top-level
      field in turn and also samples nested fields (a block's `credits`, a course's
      `title`, `electives.subjectRule`);
    - an unknown field at any level (for example `catalogYear`);
    - two blocks with the same id;
    - block credits or course credits that are not a positive whole number;
    - a course without a title;
    - a course code that is not 2–4 capital letters, a hyphen and 3 digits (for example
      `MGT321` or `mgt-321`);
    - a block whose required credits plus `choose` × the pick group's course credits, for
      each pick group, do not equal its credits;
    - a pick group with `choose` below 1, asking for more courses than it lists, or whose
      courses do not all have the same credits;
    - the same course code twice across the block required lists, the block pick groups and
      `electives.namedCourses` (`electives.legacyOnlyCourses` may repeat a block course:
      PSY 251 is in the Social sciences pick and in the legacy list, brief §5);
    - a total that is not `degreeCredits`;
    - elective `credits` not equal to `courseCount × creditsPerCourse`, or
      `minCourseNumber` greater than `maxCourseNumber`;
    - a core-block reference to a block that does not exist, `coreCredits` not equal to the
      core blocks' credits, or a sequence course that is not in a core block;
    - `grades.minimumCounting` that is not one of `grades.letters`;
    - `lastReviewed` that is neither `null` nor a valid `YYYY-MM-DD` date from 2000 on;
    - something that is not a data file at all (`null`, a list, text);
    - added after QA round 1 and the review, all refusals of data that contradicts itself:
      two blocks with the same name; a legacy-only course listed twice, or equal to a
      required course or to a named elective, or equal to a pick but with a different title
      or credits; a named or legacy-only elective whose credits are not `creditsPerCourse`;
      a sequence alternative with fewer than two courses or the same course twice, two
      alternatives with the same id, or the same core block twice; a grade letter listed
      twice, or a never-counting mark that is also a letter; no subject, or the same subject
      twice, in the elective rule; an elective course number that is not three digits.
      The message for a course listed twice names both places.
11. **Look-ups.** `findCourse` returns one place, with title and credits, for a required
    course, a pick and the named elective, however the code is typed ("mgt321", "MGT-321",
    " Mgt 321 ", "biol127", "BIOL 128") or pasted: with an en dash, em dash, non-breaking
    hyphen, minus sign or full-width hyphen instead of the hyphen, with a tab or
    non-breaking space, with a zero-width space, soft hyphen or byte-order mark, or in
    full-width letters. A pick's place says which pick group it is in (ENG 131 and ENG 140
    are group 0 of Composition; ENG 132 and ENG 141 are group 1). PSY 251 returns two places: the Social sciences
    pick and a legacy-only elective. It returns an empty list (not a listed course) for
    BIO 230 and MKT 410; whether MKT 410 counts by the elective rule is decided in F04. It
    returns an empty list without throwing for `""`, `"MGT"`, `"321"`, `"MGT 32"` and
    `"CIS 304"`. — "finds a course by code however it is typed", "finds both places of a
    course listed twice", "finds nothing for a code that is not listed".
13. **The model cannot be changed once loaded.** Writing to the curriculum, to anything
    inside it, to a look-up result or to `programs` throws. — "cannot be changed once
    loaded".
12. **The file cannot drift silently.** Checks 3–9 run against the real data file on every
    `npm test`, so an edit that breaks them fails CI. — the whole file; `npm run check`.

14. **Exceptions to the elective rule** (added by the owner's answer of 2026-11-16: CIS 304
    and CIS 415 never count). The data file names the two courses in one place only,
    `electives.subjectRule.exceptCourses`; check 7's scan covers everything else in the
    file and all of `src/`. The loader refuses an exception list that is missing, not a
    list, has a badly shaped or repeated code, names a course the rule would not let in
    anyway, or names a course the curriculum lists. — "has no CIS 304, CIS 415, replacement,
    older-code or not-offered entry", "refuses a data file whose exceptions to the elective
    rule make no sense".
